# 产品输入书（模板）

> 这是整套流程的**唯一入口**。填完这份，7 个 Agent 就能自己跑起来。
> 填写原则：**宁可写得笨，不要写得聪明**。含糊一句话，下游会放大成十种理解。

---

## 必填四项（缺任一 → G-IN-00 判 FAIL，不许开工）

### 1. 背景
这个产品要解决的事，发生在什么场景里？现在没有它的时候，人是怎么凑合的？

```
（例：我有 22 只基金持仓，每天想知道整体赚了还是亏了、哪几只在拖后腿。
现在只能一个个打开 App 看，看完还得自己心算汇总。）
```

### 2. 目标用户
**具体是谁**。写"所有人"等于没写。

```
（例：我自己。持有多只场外基金、不盯盘、每天只看一次的长期持有者。）
```

### 3. 必须解决的核心问题
最多写 **3 条**，按重要性排序。超过 3 条说明你不清楚什么最重要。

```
1.
2.
3.
```

### 4. 明确的失败定义 ★ 最容易被跳过，也最重要
**怎样就算这个产品做失败了？** 给出可判定的标准。

```
（反例："用户体验不好"  ← 无法判定）
（正例："方向预测正确率低于 60%，那这个产品对我就没有价值，不如不做"）
```

---

## 选填但强烈建议填

### 5. 已知约束
已经踩过的坑、已经验证过的结论、不能碰的红线。
**这一栏能替下游省掉大量重复探索。**

```
- 数据源：
- 技术限制：
- 已证伪路线（不要重复试）：
- 必须遵守的方法论：
```

### 6. 现有材料
已有的文档、代码、数据文件在哪？

```
-
```

### 7. 交付形态与边界
要网页 / 桌面应用 / 命令行？多少人用？要不要联网？

```
（例：本地单用户桌面工具，不联网部署，数据来自本地 JSON 文件）
```

### 8. 时间与优先级偏好
是"先跑通最小闭环"还是"一次做到位"？

```
（例：先跑通 2 只资产的最小闭环，验证后再扩展）
```

---

## 填写检查

- [ ] 核心问题 ≤ 3 条
- [ ] 失败定义可判定（有数字或明确标准）
- [ ] 目标用户具体到"什么样的人"
- [ ] 已知约束里写清了已证伪的路线
