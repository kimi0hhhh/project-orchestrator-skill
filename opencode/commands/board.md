**端口已配置** → 执行（复用已有服务 + 尝试打开浏览器）：

```
python runtime/board.py open
```

**端口未配置 / 失效 / 被占** → **先问用户要用哪个端口**，再执行：

```
python runtime/board.py open --port <用户给的端口>
```

若脚本 exit 2（端口被别的服务占用）→ 把脚本打印的**占用者原样念给用户**，
请他换一个端口再试。**不要自己换端口。**

### 最后一步（不许漏）

**把地址念给用户**，一行就够：

```
看板 → http://127.0.0.1:<端口>
```

- **不论浏览器有没有弹出来，都要念地址**。agent 在非交互 shell 里调 `webbrowser.open`
  有弹不出来的可能，念地址是唯一可靠的兜底。
- **地址从 `runtime/board.py status` 读，不凭记忆**；确认状态是「运行中」再念。
- 状态是「未运行」就先起好再念 —— **别把死地址给用户**，那比不给更糟
  （用户会以为看板坏了，然后自己去双击 HTML，看到一张死板）。

### 端口纪律（v4.4）

- **端口由用户指定，不自动分配。** 自动挑端口会让下次启动不知道去哪儿找看板；
  实测还踩过一个更糟的坑：两套实现各自挑端口，其中一套回退到默认端口时
  **撞上另一个工作区的服务并误报「已在运行」**，把用户指到别人的看板上。
- **端口一旦定下就写进 `runtime/.port`，长期沿用。** 所以「问用户」只在
  首次配置、或原端口失效/被占时才发生 —— **不是每次启动都问**（那是打扰）。
- **绝不劫持别人的端口**：认不出归属时一律按「被占」处理并报错。
- 提醒用户：**不要**双击 `runtime/ui/index.html` 本地打开
  （`file://` 下没有后端，页面永远是死的空板）。
