# 尺子（Scoring Ruler）

给多 agent 交付流程打两个分。**分数由脚本算，不由子 agent 自填**——FundLens 的 PM-D1 证明了
「自验收 7/7 全绿」可以是完全错的。

```bash
python scoring/ruler.py            # 积木分：静态检查能不能抓到历史缺陷（秒级）
python scoring/project_score.py    # 项目分：这次交付本身好不好
python scoring/verify_redgreen.py  # 红绿验证：注入已知缺陷，证明静态检查有牙
python scoring/ui_smoke.py         # UI 点击冒烟：真开浏览器逐页点一遍（S5 门禁用）
python scoring/ui_smoke.py --selftest   # 上面那条自己的红绿自检
```

## 静态 vs 运行时：两条腿

| | 查什么 | 抓不到什么 |
|---|---|---|
| `ruler.py`（静态） | 未定义标识符、字段不齐、死引用、静默吞异常 | `obj.method` 里 obj 是 undefined、作用域遮蔽、**界面点不动** |
| `ui_smoke.py`（运行时） | 真开浏览器逐页点、真报错 | 后端口径、数据正确性 |

**PM-D1 需要一个都不能少**：静态扫出「裸调用 `openEdit`」，
运行时验证「点下去真的报 ReferenceError」。缺一条都是半张网。

## ui_smoke 的三条踩坑记录（改它之前先读）

1. **必须给桌面视口**。默认 800×600 落进移动端卡片流 `.rowgrid`，
   而 `.rowgrid .c-ops{display:none}` —— 行内操作列被 CSS 藏起来，
   22 个 `···` 按钮全在 DOM 里、可见的 0 个，检查静默退化成空跑。
2. **注入脚本要等 `load`**。它插在 `</body>` 前，直接跑会赶在 `app.js`（defer 模块）
   绑定导航 `onclick` 之前，于是七页一个都进不去。
3. **弹出菜单每点一项都要重新点开**。全局 `click` 监听会在点完第一项时关闭菜单，
   剩下的项已被移出 DOM —— 第 3 项「编辑」（PM-D1 坏的那项）永远轮不到。

诊断串里**不要出现方括号**：外层解析靠 `[...]` 定界，嵌套会截断。

## 两个分各回答什么

| | 答案 | 数据源 |
|---|---|---|
| **积木分** | 我的**检查方法**好不好 | `defects.json` 题库 + 源码/契约静态扫描 |
| **项目分** | 这次**交付**好不好 | `01-requirements` × `19-pm-acceptance` × Brief §4 |

两者是手段与结果的关系，可以互相验证：积木分高 → 缺陷该在更早的门禁被自己的检查抓到，
而不是等终验。FundLens 是反例，也是第一个数据点。

## 项目分是三个独立问题，不合成总分

1. **做完了吗** —— P0 交付率 / 全体完成度 / 未交付项处置
2. **说的是真话吗** —— Brief 失败定义违反数 + 被推翻的「已完成」声明数
3. **能用吗** —— 终验结论 + 实操发现的 P0/P1 缺陷数

**为什么不合成一个总分**：加权会把「一票否决」洗成「及格」。一个项目可以 100% 完成 + 全是假的——
合成后显示 65 分，而真实情况是不能交付。

## 积木分怎么算

题库 = 该项目**真实发生过**的缺陷（已知根因与正确修法，因此可当考题）。
每条缺陷绑一块检查积木；积木跑出来是绿还是红，就是判分。

- **覆盖 + 检查绿** = 缺陷已修，尺子确认
- **覆盖 + 检查红** = 缺陷仍在，尺子抓到了 ← 价值在这里
- **无积木覆盖** = 尺子的盲区，要补新积木

三种状态都要报出来，**不能只报通过率**——盲区比失败更危险。

## 维护纪律（三条）

1. **新缺陷必须回填题库**：`04-defects` / `PM-D1` / `BLOCK-x` 每条都要指定它该由哪块积木覆盖。
   没积木能覆盖它 → 说明要造新积木，而不是记一条"下次注意"。
2. **每块新积木必须过红绿验证**：在 `verify_redgreen.py` 里加一个用例，注入该缺陷，
   断言检查变红。**没有红过的检查等于没写过。**
3. **检查要认假阳性**：如果一条检查在干净代码上就报红，先修检查再修代码。
   尺子不准比没有尺子更糟——它会训练人忽略警报。
   确认无害的个例，在该行写 `# ruler-ok: 理由` 主动豁免（必须写理由）。

## 已覆盖的积木（7 块）

### 静态（`ruler.py`）

| 代号 | 积木 | 抓什么 |
|---|---|---|
| E01 | 契约接口穷举 | 契约声明了但没实现的路由 |
| E02 | 契约字段穷举 | 两个页面字段不对齐（BLOCK-1 的形状） |
| E03 | 文档里的工件路径可解析 | 路径漂移（`docs/` 目录不存在这类，实测 14 处） |
| B01 | 前端未定义标识符 | 点了没反应（PM-D1 的静态形状） |
| B02 | 金额必须走统一格式化 | 绕过隐私打码 |
| X01 | 静默吞异常 | 失败不可感知（SHOULD-3 的形状） |
| G01 | None 参与除法的防护 | 单个异常数据行打挂整个接口 |
| G02 | json 加载必须显式兜底 | 文件损坏即崩 |

### 运行时（`ui_smoke.py`）

| 代号 | 积木 | 抓什么 |
|---|---|---|
| B03 | 逐页真点一遍 | 点了没反应（PM-D1 的运行时形状：`ReferenceError`） |

**尚未覆盖**：清单类穷举（NIT-5 那种「异常捕获清单不全」）、跨端一致性、性能阈值、
非浏览器客户端的交互。这些需要新积木。

## 已知的环境依赖

- `ui_smoke.py` 需要 **Chrome 或 Edge**（用 headless 模式）。找不到时 exit 3，
  门禁记 CONCERN，**不许静默跳过**。
- `ui_smoke.py` 需要**证据夹具**（`04_工程文档/05-qa/evidence/*.json`）。
  没有夹具时界面渲染成错误态、可点元素锐减，脚本会报出夹具覆盖率。
  **覆盖率低时"绿"的可信度打折**——这一点会打印出来，别只看绿字。
